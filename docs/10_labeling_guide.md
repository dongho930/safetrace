# 10. D1-R 2인 교차 라벨링 가이드 (v1.0)

D1-R(실제 위협 스냅샷)로 AI 유형 분석 품질(R3)을 공식 측정하기 위한 정답지 작성 절차다. 도구: 웹콘솔 **D1-R 라벨링** 탭.
구현: `backend/src/safetrace/labeling/store.py`, `api/labeling.py`, `frontend/src/components/Labeling.tsx`.

## 1. 원칙

| 항목 | 규칙 |
|---|---|
| 표본 | 수집 스냅샷의 **50%**. `SHA-256(salt:snapshot_id)` 결정적 추출이라 수집되는 대로 늘어나고, 한 번 포함된 스냅샷은 빠지지 않는다. 라벨링 시작 후 salt·비율 변경 금지 |
| 라벨러 | 2명(`SAFETRACE_LABELING_LABELERS`, 비우면 처음 라벨을 남긴 2명). investigator·reviewer 계정만 |
| 블라인드 | 라벨 화면에 **피드 출처·AI 판정·상대 라벨을 표시하지 않는다**. 상대 라벨은 두 명이 모두 판정한 불일치 건의 합의 탭에서만 보인다 |
| 독립성 | 두 명이 모두 판정한 스냅샷의 개별 라벨은 **잠긴다**. 이후 변경은 합의로만 한다 |
| 불일치 | 두 명이 논의해 **합의 라벨**과 근거(5자 이상)를 남긴다. 보고서에는 "독립 일치 N + 합의 M"으로 나눠 적는다 |
| 일치도 | Cohen's κ·일치율은 **합의 전 독립 판정**으로 계산한다(현황 탭) |
| 안전 | 수집 HTML 은 브라우저로 열지 않는다. 동결 시 SHA-256 으로 재검증한 스크린샷과 요약 필드만 본다. URL 을 직접 열어 확인하지 않는다 |

## 2. 판정 기준

**수집 시점 화면(스크린샷)에 보이는 것**으로 판정한다. 피드에 올라왔다는 사실은 근거가 아니다.

| 키 | 라벨 | 판정 기준 | 예 |
|---|---|---|---|
| 1 | 피싱 `PHISHING` | 기관·기업·서비스를 **사칭**하고 로그인·인증·결제·개인정보 입력을 요구 | 은행·택배·지갑(Trezor·MetaMask)·MS365 가짜 로그인, 환급금 본인인증 |
| 2 | 사기 `SCAM` | 사칭 로그인 없이 **금전 편취**를 유도 | 고수익 투자·코인 리딩, 가짜 쇼핑몰, 입금 유도, 경품·환급 미끼 |
| 3 | 불법도박 `ILLEGAL_GAMBLING_SUSPECTED` | 카지노·토토·슬롯 배팅, 충전·환전 안내 | 첫충·매충 보너스, 꽁머니 |
| 4 | 악성코드 `MALWARE` | 파일·앱 **다운로드·설치 유도**가 핵심 | 가짜 보안앱·APK, 가짜 브라우저 업데이트, 파일 공유 페이지의 실행 파일 |
| 5 | 기타 `OTHER` | 위협이지만 1~4에 맞지 않음 | 개인정보 수집만 하는 설문, 스팸 리다이렉트 허브 |
| 6 | 정상 `BENIGN` | 위협 징후 없는 정상 서비스 화면 | 정상 기업 홈, 호스팅 기본 페이지, 이미 복구된 정상 사이트 |
| X→1 | 제외: 주차 도메인 `PARKED` | 도메인 판매·광고 주차 페이지 | "This domain is for sale" |
| X→2 | 제외: 삭제·오류 `DOWN_OR_ERROR` | 호스팅 차단·삭제 안내, 404/5xx, 빈 화면, 로딩만 보임 | "This site has been suspended", Cloudflare 경고 페이지 |
| X→3 | 제외: 판단 불가 `UNSURE` | 위 기준으로 정할 수 없음 | 내용이 거의 없는 로그인 폼만 있고 사칭 대상 불명 |

우선순위(여러 개에 해당할 때): **피싱 > 악성코드 > 사기 > 불법도박 > 기타**. 예) 가짜 은행 로그인 후 APK 설치 유도 → 피싱.

자주 헷갈리는 경우:
- 파일 공유 서비스(Dropbox·Google Drive) 정상 화면만 보이고 파일 내용은 알 수 없음 → 파일명·설명이 설치를 유도하면 **악성코드**, 아니면 **판단 불가**.
- 호스팅 플랫폼 기본 페이지(vercel·pages.dev "Not Found") → **삭제·오류**.
- 사칭 대상이 보이지만 입력 폼이 없고 "앱 설치" 버튼만 있음 → **악성코드**.

## 3. 절차

1. `.env` 에 `SAFETRACE_LABELING_ENABLED=1`, 필요하면 `SAFETRACE_LABELING_LABELERS=["아이디1","아이디2"]` 를 넣고 API 를 재시작한다.
2. 각자 자기 토큰으로 콘솔에 로그인 → 상단 **D1-R 라벨링** → **라벨링** 탭. 단축키 1~6, X(→1~3), ←/→, N.
3. 주 1~2회 **합의** 탭에서 불일치 건을 함께 보고 합의 라벨·근거를 남긴다.
4. 10/18 동결 후 모든 표본을 마치고 내보낸다.

```powershell
.venv\Scripts\python tools\eval\export_d1r_labels.py       # data/d1r/labels.csv + κ 요약
.venv\Scripts\python tools\eval\replay_d1r.py               # HAR 재생 평가 → reports/d1r_eval.json
```

## 4. 보고

- 표본 수, 두 명 완료 수, 독립 일치율·κ, 합의 건수, 제외 사유별 건수
- R3 Macro-F1 은 최종 라벨(일치+합의) 기준, 참고로 독립 일치분만의 값도 함께 적는다
- 라벨링 이벤트 원본(`data/d1r/labels/events.jsonl`)은 수정하지 않는다(추가 전용, 누가·언제 기록)
